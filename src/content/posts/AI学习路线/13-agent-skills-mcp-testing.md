## Skill 与工具不是一回事

**工具**提供动作，例如查数据库；**Skill**提供完成一类任务的程序性知识，例如“如何生成月报并验证”。Skill 通常包含触发条件、步骤、所需工具、参考资料、脚本和完成标准。它应该可复用、范围窄、能被测试。

一个好 Skill 回答：

1. 什么时候触发，什么时候不触发；
2. 需要哪些输入与权限；
3. 步骤和分支是什么；
4. 如何验证产物；
5. 失败如何恢复。

不要把所有规则塞进一个巨大 Skill；触发描述重叠会让路由不稳定。可确定的计算优先写脚本，模型负责判断与编排。

## MCP 的角色

Model Context Protocol 用统一方式把外部服务器提供的 tools、resources、prompts 暴露给宿主。MCP 解决“如何发现与调用能力”，不替代业务权限、安全审计和工作流。

```text
Agent Host ── MCP Client ── MCP Server ── Files / DB / SaaS
     │             │              │
  决策与循环     协议与会话      能力与数据边界
```

服务器应提供最小权限工具、清晰 schema、分页、幂等性和结构化错误。写工具最好支持 dry-run；密钥留在服务器端。资源是可读取上下文，不应伪装成无副作用工具。

## 测试金字塔

- **单元测试**：参数校验、路径规范化、答案解析、奖励函数。
- **契约测试**：工具 schema、必填字段、错误码和版本兼容。
- **集成测试**：Agent—MCP—真实/沙箱服务的交互。
- **端到端测试**：从用户目标到最终可验证结果。
- **回归评测**：固定任务集比较 prompt、模型、skill 版本。

LLM 输出非确定，断言应关注结构和语义，而非整段字符串完全一致。能确定的部分仍应严格断言，例如“不允许越过工作区”“写操作必须确认”。

```python
def test_path_stays_in_workspace(tool):
    result = tool.read_file("../../secret.txt")
    assert result.error_code == "PATH_OUTSIDE_WORKSPACE"
```

## 模拟、录制与故障注入

单元测试用 fake 工具；集成测试可录制稳定响应，但要清除密钥和个人数据。主动注入超时、429、空结果、格式损坏、部分成功，验证 Agent 是否重试、降级或停止。

安全测试至少覆盖 prompt injection、路径穿越、命令注入、SSRF、秘密外泄、越权写入和重复副作用。用户授权范围必须在执行层强制，而不是只写在 prompt 里。

## 轨迹调优

先用评测定位瓶颈，再改 Skill：

- 工具选错 → 改工具描述/路由示例；
- 参数错 → 收紧 schema、加预处理；
- 步骤遗漏 → 明确检查表与完成条件；
- 循环 → 加重复检测和预算；
- 最终答案错但工具结果对 → 改结果汇总模板。

每次只改变一个版本因素，保留完整轨迹。成功率上升但成本翻十倍，未必是好改进。

## 本章检查点

写一个论文检索 Skill，连接一个只读 MCP/模拟服务器；提供 10 个正常任务、5 个边界任务、5 个恶意输入；测试触发率、结果正确率、越权率、平均调用数和失败恢复。
