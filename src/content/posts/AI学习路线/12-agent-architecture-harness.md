## Agent 与聊天模型的区别

Agent 是“模型 + 状态 + 工具 + 控制循环”。模型不直接改变世界，而是提出动作；Harness 校验和执行，再把观察返回模型：

```text
目标 → 观察 → 计划 → 选择工具 → 参数校验 → 执行
   ↑                                      ↓
   └──── 结果/错误 ← 记录轨迹 ← 状态更新 ──┘
```

Harness 是承载这个循环的工程系统：提示组装、工具注册、上下文压缩、权限、超时、重试、沙箱、日志、评测和用户确认都属于它。

## 规划

简单任务直接 ReAct：思考当前动作、执行、观察、继续。复杂任务使用显式计划，把目标拆成有完成条件的步骤。计划不是一成不变；工具失败或新证据出现时应重规划。

避免把“写一个很长计划”当能力。有效计划必须能映射到动作，且任一时刻知道：已完成什么、下一步是什么、什么条件算结束。

## 工具

每个工具需要窄 schema、明确副作用和结构化错误。读取与写入分开；删除、付款、发送消息等高影响动作要求确认。执行层必须做参数校验，不能相信模型生成的路径、SQL 或 URL。

把网页/邮件返回中的 prompt injection 当作不可信数据。工具结果应标记来源，秘密按最小权限提供，避免把整个环境变量或用户目录暴露给模型。

## 记忆

- **工作记忆**：当前上下文中的目标、计划和最近观察；
- **情节记忆**：过去任务轨迹和结果；
- **语义记忆**：稳定事实与用户偏好；
- **程序记忆**：可复用 skill/流程。

记忆写入应有来源、时间、置信度和过期策略。模型“推测的事实”不能静默存成长期记忆。检索记忆后仍要判断是否与当前任务相关、是否过时。

## 执行与终止

设置最大步数、token、时间、费用和重复动作检测。工具失败要区分可重试临时错误与不可重试参数错误。连续调用同一工具得到相同错误时，应停止并报告，而不是循环。

完成条件必须由可观察证据支持：代码任务要测试/构建，研究任务要来源与数据，外部写操作要确认返回状态。

## 轨迹与 Agentic Learning

轨迹记录每一步输入、动作、观察、延迟、token、错误和最终结果。可用成功轨迹做 SFT，成对好坏轨迹做偏好学习，可验证任务用 RL。训练前先清洗隐私、工具噪声和偶然成功，避免模型学习冗长或危险动作。

Agent 评测除了最终成功率，还看工具选择正确率、无效调用数、恢复能力、成本、延迟、安全违规和人工接管率。

## Codex、Claude Code、OpenClaw、Hermes 的位置

它们都是 Agent/Harness 的具体实现，但侧重点不同：Codex 是面向软件开发的 coding agent，可理解、修改、审查、调试和验证代码；Claude Code 偏终端编码工作流；OpenClaw 强调个人助理、工作区、渠道、技能与持续运行；Hermes Agent 强调工具、记忆、技能和可自我改进的工作流。产品迭代快，安装与能力以各自官方文档为准。

选择时不要只比模型回答：比较权限模型、工具生态、隔离、日志、可编程性、部署位置和数据边界。
